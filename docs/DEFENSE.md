# Защита лабораторных работ №1 и №2

## Что подготовить до защиты

Откройте три окна: два терминала и браузер. PostgreSQL должен быть запущен через Postgres.app.

Терминал 1 — backend:

```bash
cd backend
source .venv/bin/activate
python -m app.init_db
uvicorn app.main:app --reload
```

Терминал 2 — frontend:

```bash
cd frontend
npm install
npm run dev
```

В браузере заранее откройте две вкладки:

- frontend: `http://localhost:5173`;
- Swagger: `http://127.0.0.1:8000/docs`.

Перед началом можно показать историю разработки:

```bash
git log --oneline --decorate -5
```

## Лабораторная работа №1

### Короткий текст защиты

> Цель первой работы — определить экраны и пользовательские сценарии проекта и создать первоначальный интерфейс на React и TypeScript. Мой проект LabTracker предназначен для учёта учебных курсов и заданий. Для интерфейса я использовал Ant Design, а общую сетку и адаптивность реализовал собственным CSS. Навигация сделана через React Router. На первом этапе backend ещё не подключён, поэтому данные берутся из mock.ts. Типы курса, задания, статуса и вида работы описаны в types.ts. Реализованы сводка, список и карточка курсов, список и карточка заданий, а также формы создания и редактирования.

### Что показать

1. Откройте сводку `/`. Покажите счётчики, ближайшие дедлайны и просроченную работу. Скажите, что сводка вычисляется на клиенте из массива заданий.
2. Откройте «Курсы», затем карточку курса. Покажите переход без перезагрузки страницы и связанные задания.
3. Откройте «Задания». Выберите фильтр по курсу или статусу и покажите, что список меняется.
4. Откройте карточку задания, затем форму редактирования. Объясните, что сохранение пока демонстрационное и будет подключено к API в ЛР №5.
5. При необходимости сузьте окно браузера и покажите базовую адаптивность.

### Какие файлы открыть в редакторе

- `frontend/src/main.tsx` — запуск React и тема Ant Design;
- `frontend/src/App.tsx` — страницы, компоненты и маршруты;
- `frontend/src/mock.ts` — демонстрационные данные;
- `frontend/src/types.ts` — типы TypeScript;
- `frontend/src/styles.css` — собственные стили и адаптивность.

## Лабораторная работа №2

### Короткий текст защиты

> Цель второй работы — реализовать серверную часть на FastAPI, модель данных и CRUD через PostgreSQL и SQLAlchemy. Backend разделён по назначению: config читает параметры окружения, database создаёт engine и сессии, models описывает таблицы и связи, schemas проверяет запросы и формирует ответы, services содержит операции с данными и бизнес-проверки, routers объявляет HTTP-маршруты, а main собирает приложение. Реализованы связанные таблицы courses и assignments. Один курс содержит много заданий, внешний ключ использует ON DELETE CASCADE. Для заданий работают создание, чтение, изменение, удаление, фильтры и сортировка. Pydantic и ограничения PostgreSQL не позволяют выставить оценку вне шкалы. Отсутствующие записи возвращают 404, некорректные данные — 422.

### Что показать в Swagger

Выполняйте операции кнопками `Try it out` → `Execute`.

1. `GET /health` — API запущен.
2. `POST /api/courses` — создайте курс:

```json
{
  "title": "Базы данных",
  "description": "SQL и проектирование реляционных БД"
}
```

Запомните полученный `id` курса.

3. `POST /api/assignments` — создайте задание, подставив `course_id`:

```json
{
  "course_id": 1,
  "title": "Лабораторная работа №2",
  "description": "Спроектировать связанные таблицы",
  "type": "lab",
  "status": "in_progress",
  "deadline": "2026-10-10T18:00:00+03:00",
  "max_grade": 10,
  "grade": null
}
```

4. `GET /api/courses/{id}` — покажите курс и вложенный массив `assignments`.
5. `GET /api/assignments` — задайте `status=in_progress`, `type=lab`, `sort=deadline_asc` и покажите фильтрацию.
6. `PATCH /api/assignments/{id}` — завершите задание:

```json
{
  "status": "graded",
  "grade": 8.5
}
```

7. Повторите `PATCH` с `grade: 11`. Покажите статус 422 и сообщение о недопустимой оценке.
8. Выполните `GET /api/assignments/999999`. Покажите статус 404 и сообщение «Задание не найдено».
9. В самом конце можно удалить курс через `DELETE /api/courses/{id}` и объяснить, что его задания удаляются каскадно.

### Какие файлы открыть в редакторе

- `backend/app/config.py` — настройки из `.env`;
- `backend/app/database.py` — engine, сессия и создание таблиц;
- `backend/app/models.py` — таблицы, внешний ключ и ограничения;
- `backend/app/schemas.py` — DTO и валидация;
- `backend/app/services.py` — CRUD и бизнес-проверки;
- `backend/app/routers/` — API-маршруты;
- `backend/app/main.py` — сборка FastAPI-приложения;
- `backend/tests/` — автоматическая проверка схем и CRUD.

## Короткие ответы на вероятные вопросы

**Почему frontend ещё не использует API?** По плану курса интеграция выполняется в ЛР №5; в ЛР №1 разрешены демонстрационные данные.

**Почему нет авторизации и пользователей?** Регистрация, JWT и проверка владельца относятся к ЛР №4. Во второй работе проверяется CRUD предметных сущностей.

**Чем модель SQLAlchemy отличается от схемы Pydantic?** SQLAlchemy описывает хранение в PostgreSQL, а Pydantic — формат входящих и исходящих данных API и их валидацию.

**Как реализована связь?** В `assignments.course_id` находится внешний ключ на `courses.id`; ORM-связь позволяет получить задания курса. `ON DELETE CASCADE` удаляет зависимые задания вместе с курсом.

**Где хранятся параметры подключения?** В локальном `.env`; в Git хранится только безопасный пример `.env.example`.

**Как создаются таблицы?** Команда `python -m app.init_db` вызывает `Base.metadata.create_all`. То же выполняется при запуске API.

**Как проверялся backend?** Командой `pytest -q`: отдельно проверяется Pydantic-валидация и полный CRUD-сценарий против PostgreSQL.
